# Dogfood interface changes

Preserve Dogfood's existing brand, real data and evidence semantics.

For working screens, state the user's main question and next action, then inspect the rendered screen before editing. Essential work, blockers, task links and acceptance requirements must be visible in the relevant view. Use named views for different jobs and a list/detail layout for repeated objects. Do not hide these behind nested accordions. Reserve disclosures for optional technical material, raw receipts, long briefs and older conversation history.

Check the affected flow in the existing browser at desktop and phone widths. Navigation and polling must preserve drafts, selections and keyboard focus. Keep audit completion, accepted work and closed conversations distinct.
