dogfood

Plan, build and prove web projects.

Feeling

A calm workbench for turning intent into proven work. The project, next outcome and evidence carry the interface.

Principles

  • One clear next action per view.
  • Remove repeated explanations and decorative containers.
  • Keep agent work inspectable by people.
  • Accepted evidence must describe the current checkout.

Logo

A friendly front-facing dog with folded ears: a distinctive original mark for a workbench where software gets tried.

Clear space

Keep at least one quarter of the symbol width clear around the blue tile.

Smallest size

16px favicon; 32px navigation mark; 40px on first run.

Never

  • Stretch the tile, alter the face proportions or add decorative effects.
  • Use the brand blue as a page background.
  • Replace real status with the brand mark.

  • Navigation. 32px dog mark, restrained wordmark, project picker and neutral section icons; blue identifies selection and primary actions.
  • Project selector. One chevron 12px inside the right edge. Reserve text padding; never layer a native arrow with a custom arrow.
  • Work list. Short outcome rows beside the selected task and its receipt; selected detail leads on phones.
  • Page report. Computer and phone captures, then six plain answers; open detail to inspect evidence.
  • Forms. Visible labels, one Save action, clear Cancel and errors; optional settings stay behind a disclosure.
  • Documents. Readable text and a real sandboxed brand guide with a full-page escape.
  • Agent board. Flat divided lanes and readable request cards reflect actual execution state. Threads use a 76ch reading measure. A finished turn enters Review; Done never substitutes for QA acceptance.

Voice

How dogfood talks.

Tone

  • Plain and specific
  • Calm about failures
  • Clear about the next step

Say

  • Good
  • Needs work
  • Not checked
  • Accepted
  • What did you see?

Never

  • Implementation names in human empty states
  • Fabricated readiness
  • Repeated setup instructions
Plan

“Track the work and the checks that prove it is done.”

Evidence

“The checkout changed. Run the checks again before accepting.”

Imagery, icons and motion

Imagery

Real project screenshots are the primary imagery.

  • Keep captures honest about device and age.
  • Show complete evidence when requested.
  • Never: Stock photos, decorative AI imagery or fake browser content.

Icons

Small consistent line icons for navigation; shaped status marks communicate state.

  • Never: Decorative icon bubbles or duplicated dropdown arrows.

Motion

  • Use only restrained feedback and native disclosure behavior.
  • Remove nonessential transitions when reduced motion is requested.

Accessibility

  • WCAG AA text contrast in both themes.
  • Visible keyboard focus and complete keyboard paths.
  • Every control has an accessible name; form errors explain recovery.
  • Test at 1280 and 390 wide with substantive content.
  • Status uses a word or shape as well as color.
